## 部署

同步需全班共用密碼：由老師親自在專案設定的指令碼屬性新增 `CLASS_SYNC_PASSWORD`，值填專用密碼。密碼不存於 GitHub 或瀏覽器儲存空間；每次按同步鍵輸入，後端對上傳及刪除逐一驗證。未設定時拒絕同步。

1. 用擁有上述試算表的 Google 帳號登入 https://script.google.com/ ，建立新專案。
2. 將本資料夾 Code.gs 的內容放到專案的 Code.gs。
3. 新增 HTML 檔案，名稱為 Index，把本資料夾 Index.html 的全部內容貼進去。
4. 在專案設定顯示 appsscript.json，使用本資料夾的設定檔（V8、Asia/Taipei、試算表存取權限）。
5. 在編輯器選擇 initializeSpreadsheet 並執行一次。由帳號擁有者審查並完成 Google 授權。程式會核對目前帳號是否為執行擁有者；匿名學生無法初始化工作表。額外的 userinfo.email 權限只用於這項擁有者核對。
6. 填妥學生名單；不會自動建立假學生。名單空白時登入會提示老師加入資料。
7. 「部署 → 新增部署 → 網頁應用程式」。執行身分選擇擁有者，存取對象依班級需求選擇；若要學生無 Google 帳號也可使用，需有「任何人」選項，學校帳號政策可能限制此選项。
8. 部署後使用 /exec 網址。此版本的前端也由 Apps Script 提供，原 GitHub Pages 網址仍為本機儲存版本，不會直接呼叫此後端。
9. 需要更新時，先從專案根目錄執行 node build-apps-script.mjs，再更新 Google 專案裡的 Index.html 與 Code.gs；部署管理中建立新版本。

## 實際驗證

1. 用名單內的學號與姓名登入，錯誤姓名應被拒絕。
2. 選擇「純記桿數」，完成前 9 洞，儲存到歷史紀錄。
3. 儲存後顯示「僅存於本機，尚未同步」，試算表應不增加；按「同步到後端」後才上傳，確認成功狀態與新列。
4. 重試同步，確認相同紀錄編號沒有重複列。
5. 換裝置或無痕視窗登入，確認同一學生可讀回紀錄；其他學生只讀到自己的紀錄。
6. 測試斷網儲存，紀錄留在本機與待傳佇列；恢復網路或重新登入都不自動上傳，須按「同步到後端」。登入逾期時須重新登入。
7. 模擬球場的歷史紀錄不會上傳。
8. 在網站刪除純記桿數紀錄後，按「同步到後端」才將工作表那一列標記為「已刪除」，讀回時排除它。

## 範圍與限制

- 僅同步儲存進歷史的純記桿數紀錄，不同步尚未完成的單洞草稿、模擬模式或個人球場設定。
- 原來只存在 GitHub 網址瀏覽器中的資料，因網站來源不同，不會自動搬入新網址。需另行匯入既有紀錄才會遷移。
- 新儲存的純記桿數按「同步到後端」才會上傳。同次按鍵只處理當下待同步變更；同步期間新儲存的紀錄需再次按鍵。登入只讀取歷史。舊有沒有同步標記的本機歷史不會自動上傳。
- Apps Script 有免費配額與同時執行限制，班級同時儲存需在部署後測試。使用 ScriptLock 防止同時改寫、固定紀錄編號避免重複新增。
- 學號與姓名是名單核對，並非強身分驗證；知道兩者的人可以冒用。正式學生資料應由老師管理試算表分享權限。
- 電腦模擬測試已通過。2026-10-01 已部署版本 2，以學號 412235053、姓名 JASON 真實登入並儲存兩筆前 9 洞各 27 桿測試紀錄；已核對試算表資料，重新登入也能讀回。多人並發仍需實際班級測試。
